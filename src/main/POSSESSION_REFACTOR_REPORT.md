# Текущий этап: Player Body для Zombie

Рабочее дерево перед началом было чистым, HEAD — `70e9f31a19771cf123ab6d4ddda2322115db2211`; дополнительный checkpoint не требовался.

Обычный `minecraft:zombie` теперь выбирает уже существующий путь Skeleton/Blaze. Единственная производственная правка этого этапа — добавление типа Zombie в `usesBeta16PlayerBody`. Функции движения Skeleton/Blaze, скорость, повороты, камера, руки, `MouseHandlerMixin`, `xBob/yBob`, phasing, сетевые обработчики и интерполяция не редактировались.

## Почему это устраняет различие путей

```text
Раньше Zombie:
  клавиши → custom input packet → серверный host.aiStep/travel → позиция моба по сети
  камера = моб → клиент показывает интерполированный серверный результат

Теперь Zombie, как Skeleton:
  клавиши → LocalPlayer.aiStep/Player.travel/move → локальное предсказание камеры игрока
  vanilla movement packets → серверная проверка положения игрока
  PlayerTick.END → syncBeta16HostToPlayer → серверное положение/повороты отображаемого Zombie
  стандартный entity tracker → остальные игроки видят положение Zombie
  host.aiStep → общий диспетчер пропускает вторую физику отображаемого тела
```

Серверная синхронизация не отключена. Игрок остаётся физическим исполнителем, а существующий PlayerMixin берёт размеры/высоту глаз тела. Zombie использует имеющееся масштабирование скорости humanoid и vanilla наземные прыжок, гравитацию, спринт и коллизии. В режиме пассажира предикат Player Body по-прежнему выключается, поэтому Zombie + Zombie Horse остаётся на существующем пути транспорта.

## Проверки Zombie

Новый `ZombiePlayerBodyGameTests`:

- Выбор Player Body, камера игрока, размеры тела, реальные вызовы `player.aiStep`, перенос координат/yaw/pitch на host, отсутствие второго движения `host.aiStep`.
- Все четыре направления WASD, увеличение скорости при спринте, торможение и остановка на нейтральном вводе.
- Прыжок, падение/приземление, столкновение со стеной по hitbox игрока и согласованное положение host.

Существующие проверки гравитации/столкновения Zombie теперь проверяют игрока как физического исполнителя. Тесты ещё существующего native/custom-packet пути сохранены на Husk; они не удалены и их условия не ослаблены. Существующая проверка поворотов Zombie включает штатный вызов syncBeta16HostToPlayer. Регрессионные тесты Skeleton/Blaze и езды не переписаны.

Итог: `compileJava` и `reobfJar` успешны; `runGameTestServer` — 251 тест, 244 прошли, 7 ошибок совпадают с исходным baseline. Все три новых теста Zombie прошли. Полный Gradle-запуск возвращает ошибку из-за семи известных тестов. Имена сверены по stdout; одновременно запущенный клиент перезаписал latest.log, поэтому сводка сохранена в `possession-zombie-gametest-result.txt`.

## Граница этапа и ручная проверка

Плавность и отсутствие рывков ещё не подтверждены визуально. GameTest проверяет вызовы физики и результат координат, но не frame pacing, ощущения камеры, реальный сетевой RTT или коррекции удалённого сервера. Клиентский лог показывает запуск мира и вселение в Zombie в ходе проверки пользователем; это не подтверждает плавность. Визуальная проверка мной не выполнялась.

Для проверки: перезапустить клиент с текущей сборкой, в одном тестовом мире сравнить Skeleton и Zombie: W/A/S/D, диагональ, спринт, прыжок, отпускание клавиш, повороты, стену/ступеньки, предмет в руке, атаку, выход из тела и Zombie Horse. На сервере дополнительно проверить наблюдение второго игрока. Если рывки остаются, указать, дёргается ли камера или только модель, и одиночный это мир или сервер.

Остальные категории пока не перенесены: пользователь потребовал сначала добиться плавности Zombie. Запрошен результат ручного сравнения. Не следует включать Player Body для всех одной проверкой типа: тогда специальные travel перестанут выполняться, а их физика не появится автоматически у Player.

Аудит имеющихся 172 профилей выявил 46 вариантов полёта, 12 JUMPY, 14 лазящих, 23 с прыжками на суше у водных, отдельные SINKING/FLOATING и два phasing-типа. После подтверждения Zombie им нужны адаптации физического игрока на обеих сторонах (видовые прыжок/вода/полёт/лазание), синхронизация профиля на удалённый клиент и сохранение анимационного состояния host. Эти изменения в текущую сборку не включены. Общая цель переноса всех поддерживаемых видов остаётся незавершённой.

# Переработка управления possession

Контрольный коммит до переработки: `acc0be565d3d05cd0d3ff13c2d09dc84c89a013f`.
В него вошло единственное исходное изменение — тесты phasing в CoreDataGameTests.java.

## Архитектура

Клиентские клавиши и мышь → PossessionInputPacket → серверный снимок ввода → подготовка тела → PossessionMovementController.travel в единственной точке вызова travel из LivingEntity.aiStep.

### Фактические пути вызовов после продолжения

```text
Обычное тело:
  ClientTick.END → sendPossessionInput → network.enqueueWork → updatePossessionInput
  Entity.tick → LivingEntity.aiStep.HEAD → preparePossessedHostForAiStep → controlHost
    → vanilla serverAiStep (автономный AI захваченного тела подавлен MobMixin)
    → vanilla блок прыжка (старый AI jumping сброшен; пользовательский прыжок уже подготовлен)
    → PossessionMovementController.travel → redirectPossessedTravelVector → prepareTravel
    → динамический body.travel → штатный move/гравитация/трение данного вида
    → aiStep.RETURN → finishPossessedHostAiStep (ориентация, без повторной физики)

Skeleton/Blaze без транспорта:
  LocalPlayer: vanilla input → Player.aiStep/travel → move → vanilla movement packets
  ClientTick.END: тот же PossessionInputPacket; Blaze verticalSpeed для локального предсказания
  Server PlayerTick.END → inputForPlayer → applyBeta16MobilityToPlayer (Blaze verticalSpeed)
    → syncBeta16HostToPlayer (absMoveTo, вращение, визуальная скорость, предмет)
  host.aiStep → общий PossessionMovementController.travel
    → calculateEntityAnimation; travel и move отображаемого тела НЕ вызываются
  ClientVagrantState → syncBeta16HostToPlayer для отображения на клиенте

Транспорт:
  host — пассажир; собственное движение пассажира не управляет транспортом
  vehicle.aiStep.HEAD → prepareRiddenVehicleControl → единственный прыжок/снимок ввода
    → serverAiStep (паук сохраняет AI; управляемая лошадь не блуждает)
    → общий controller.travel → проверка актуального AI паука → восстановление осей
    → собственный vehicle.travel → move
    → aiStep.RETURN → очистка снимка/синхронизация пассажира
```

У путей разные физические исполнители, но они выбираются взаимоисключающе: player, mob или vehicle. Горизонтальный ввод Player Body остаётся vanilla-потоком с клиентским предсказанием, пользовательский пакет не применяет его повторно на сервере. Общая вертикальная формула Blaze используется клиентом и сервером на разных экземплярах сущности. Это не два последовательных физических шага одного тела.

До продолжения отображаемый host получал скорость игрока, затем travel с нулевыми осями мог снова интегрировать эту скорость. Теперь общий диспетчер исключает именно этот вызов; vanilla-анимация остаётся. Наземные тела получают только native gravity/friction. У летунов коэффициент inertia профиля задаёт затухание запрошенной скорости, затем родной travel применяет своё сопротивление; это явно составные коэффициенты, а не повторный вызов интегратора. Особенности после super.tick (например, Vex.noPhysics и Slime.squish) сохраняются.

Порядок проверен по локальным исходникам Minecraft 1.20.1/Forge и GameTest с реальным aiStep и полным tick. Другой мод, самостоятельно вызывающий move вне этого пути, всё ещё требует отдельной проверки.

- Снимок содержит WASD, Space, Shift, yaw/pitch, Sprint, UUID тела, измерение и серверное время получения. Через 10 тиков без пакетов оси и кнопки становятся нейтральными. При открытом GUI клиент явно отправляет нейтральный ввод, включая вертикальное предсказание Blaze. Отрицательный возраст и несовпадение тела/измерения также отвергаются. Смена измерения очищает снимок и освобождает оставшееся в старом мире тело; suspend/resume очищают ввод, при сохранении тела на выходе обнуляется скорость.
- Перед физикой PossessionManager задаёт ориентацию, скорость вида, прыжок, лазание и пассивные особенности. Повторное выполнение этой подготовки внутри travel удалено.
- LivingEntityMixin перенаправляет единственный вызов travel в aiStep через общий диспетчер, поэтому перехват охватывает также переопределения FlyingMob, Squid и модовых классов. Сам вызов физики остаётся в Minecraft.
- PossessionMovementController готовит скорость для полёта и Squid, который игнорирует обычный вектор ввода. Для Squid также синхронизируется внутренний movement vector, используемый следующим обновлением инерции и анимации. Контроллер не вызывает move или travel. Для наземных и остальных водных существ сохраняется собственный travel.
- Жёсткое обнуление горизонтальной скорости после отпускания клавиш удалено: наземное торможение выполняется vanilla-физикой. Удалён неиспользуемый ручной путь moveSpecialMobilityHost.
- Для Alex’s Mobs общий контроллер синхронизирует доступный setFlying(boolean), чтобы собственные навигация и анимация крыльев соответствовали полёту; отсутствие такого метода допускается. Перед первым изменением сохраняется isFlying в NBT; release восстанавливает его и удаляет снимок. NBT переживает сохранение на disconnect. Проверены включение, сохранение в воздухе, выключение на земле и восстановление исходных false/true для Crow. Профили из entity_mobility.json сохраняют приоритет. registerResolver позволяет подключать адаптеры модов. Для неизвестного типа учитываются FlyingMob/FlyingAnimal/WaterAnimal и тип навигации; иначе остаётся native travel с исходными флагами физики.
- Коэффициенты суши/воды применяются к скорости соответствующего тела. Sprint передаётся явно; протокол сети повышен с 15 до 16, клиент и сервер должны использовать одинаковую сборку.
- Освобождение очищает оси ввода и спринт, затем восстанавливает прежние параметры тела.

### Граница совместимости Skeleton и Blaze

Существующий beta16 Player Body сохранён: физическим телом этих профилей остаётся игрок, а моб синхронизируется с ним. Камера, MouseHandlerMixin, xBob/yBob, руки и предметы не переписаны. Это адаптер физического исполнителя player; общего перехода всех видов на физику сущности-моба не требуется. В нём остаются прежние NoAI/noPhysics у отображаемого тела; новые обычные/водные/летающие тела на этот режим не переведены. Адаптер сохранён осознанно: удаление Player Body не нужно для устранения конкурирующей физики и изменило бы предсказание/камеру. Его отображаемый моб теперь не выполняет второй travel.

### Транспорт и способности

Ввод транспорта сохраняется до travel, поскольку MoveControl может обнулить его после подготовки. Снимок потребляется один раз и очищается в конце aiStep. Если AI паука запускает навигацию или получает цель в этом же тике, он сохраняет приоритет. Повторяются только оси/скорость/ориентация, не физика и не прыжок. Удалён временный намеренно падающий диагностический тест. Сохранены существующие ветви управления Spider и undead Horse, приоритет самостоятельного AI паука, запрет его прыжка и ускорения спринтом. Общий контроллер не перехватывает физику самостоятельного транспорта. Обработчики атак, cooldown, владельцев снарядов, агрессии, инвентаря и phasing не заменены.

Скриншот и визуальное управление через инструмент недоступны; камера, руки, длительные анимации и ощущения управления требуют ручной проверки. Полный цикл реального переподключения и повторного входа не проверен.

Адаптер Player Body намеренно сохранён для Skeleton/Blaze как делегирование физики игроку. NoAI/noPhysics относятся к отображаемому мобу; его travel исключён общим диспетчером. Формальное удаление этих флагов не является критерием завершения текущего уточнённого запроса. Общее управление для остальных тел не использует NoAI для отключения физики и не добавляет ручной move/travel. Сохраняется возможность подключить дополнительные адаптеры, если сторонний моб выполняет самостоятельные перемещения вне штатного travel.

Профили перечисляют больше видов, чем проверено в игре. Вся матрица уникальных способностей и анимаций Alex’s Mobs не проверена; автоматические тесты трёх представителей не означают полную совместимость каждого вида. Blacklist, инвентарь и код phasing не изменены.

## Дополнительные проверки текущего продолжения

- Phantom, Vex, Rabbit, Frog, Slime, Dolphin: полный entity.tick с движением вверх/вперёд, затем 50 тиков нейтрального ввода. Rabbit/Frog/Slime должны приземлиться. Все шесть атакуют настоящую цель через handleAction; повторный удар в том же тике запрещён cooldown даже после снятия hurt immunity цели; release очищает cooldown.
- Все виды из первоначальной матрицы проходят native aiStep с нейтральным вводом и восстановление исходных флагов тела после release. Исходное состояние здесь — после удаления души, непосредственно до possession; removeSoul сам меняет флаги физики.
- CountingZombie: один travel на aiStep и один jumpFromGround даже при оставшемся AI-флаге jumping. Skeleton/Blaze: скорость игрока не сдвигает визуальный host в его aiStep.
- Crow: native isFlying/setFlying; тест не подменяет методы мода. Анимационное состояние проверено, внешний вид кадров не проверен.
- Blaze: до выстрела цель цела и не горит; создаётся SmallFireball с владельцем host; после настоящего полёта/столкновения здоровье снижается и fireTicks положителен. Фиксированный разброс и неподвижная цель изолируют collision, но не доказывают точность по движущейся цели. Код нанесения урона/поджигания в тест не добавлен.
- Skeleton+Spider, Skeleton+Skeleton Horse, Zombie+Zombie Horse: существующая серия riding-тестов плюс реальные aiStep движения. Проверяются приоритет AI паука, ответная агрессия/сброс при ударе пассажира, запрет повторной посадки при агрессии, отсутствие сброса из-за посторонней цели, Shift, нормальная скорость и запрет прыжка паука.
- Клиентский архив `run/logs/2026-10-17-3.log.gz`: 511 строк, нет ERROR/FATAL; единственное сообщение с RuntimeException относится к авторизации Realms. Это лог ранее запущенной сборки; новый клиент в текущем продолжении не запускался. Итоговые правки требуют перезапуска клиента.
